Steam Installs

Probe failed downloads, then bypass the broken path.

When Windows Steam under GPTK reaches the end of a game download and reports a corrupt download, RipperMoonKit now has a probe command and a native SteamCMD fallback.

Why This Exists

The Resident Evil Village test repeatedly failed during final depot staging with Unpack failed and Corrupt download. The same failure happened with esync disabled, on an external library, and on the local C: drive. That points away from drive format and toward the Windows Steam install path under GPTK/Wine.

Probe First

Start or retry the download in Steam, then run the probe from Terminal. It records manifest state, staged depots, install folders, disk state, and recent Steam content errors.

gptk-steam-probe \
  --appid 1196590 \
  --depot 1196591 \
  --library /Volumes/GAMECORE-1/SteamLibrary

Use a snapshot when you only need the current state:

gptk-steam-probe --appid 1196590 --snapshot

Use SteamCMD Fallback

If Steam fails the same way again, try native SteamCMD. This asks Valve's command-line client to fetch Windows-platform content outside the Windows Steam GUI.

gptk-steamcmd \
  --appid 1196590 \
  --login USERNAME \
  --target-root /Volumes/GAMECORE-1/SteamCMDLibrary \
  --name ResidentEvilVillage

SteamCMD may ask for your password and Steam Guard code in Terminal. RipperMoonKit does not store the password.

Limits

  • Some client games do not allow SteamCMD downloads even when the account owns them.
  • Some games still need Windows Steam running at launch for Steam APIs, ownership checks, or networking.
  • The downloaded folder may not automatically appear as installed in the Windows Steam GUI.
  • Treat the result as a copied game folder: make a RipperMoonKit profile pointing at the downloaded executable.

Patch Track

The probe output gives future Wine/GPTK patch work a stable target: Winsock assertions, missing Steam networking IOCTL behavior, file locking, staged depot replacement, and final manifest commit behavior.
